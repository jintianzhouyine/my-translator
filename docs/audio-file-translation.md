# 音频文件翻译与字幕回放

点击顶部「音频翻译」，选择本地文件、目标语言，然后点击「开始翻译」。沿用「设置 → 翻译引擎 → Qwen」中已保存的百炼密钥、业务空间和地域；不需要麦克风、录屏权限或虚拟音频设备。

选择文件和分段时只在本机处理，点击开始后才向百炼发送音频，产生模型调用费用。模型仍为 `qwen3.8-livetranslate-flash-realtime`，每个请求使用独立的文字翻译会话，按约 100ms 一包发送。

## 加速、重试与跳过

- 默认「加速：2 段并行」，同时最多处理两个请求。选择的原音频会在已有分割点范围内继续细分，每个请求最多处理 2 分钟；只有一个片段且超过 30 秒时至少分成两段。手动导入的已切分文件保持原文件边界。也可选择「顺序：1 段处理」保留原分段。
- 每路音频保持原采样率与约 1 倍发送速度，双路并行缩短总等待时间；短录音、服务端排队、网络和限流都会影响实际提速，不保证两倍速度。发送节奏已包含读取 PCM 的时间，避免额外累积等待。
- 模型返回的中间译文会即时显示在「正在生成」区域，定稿后进入字幕列表；未定稿文字不导出。
- 默认对网络中断、超时、服务故障及限流最多自动重试 2 次，分别等待 2 秒、5 秒。可以改为重试 1 次或关闭。所有片段和重试共享最小 7.5 秒的建连间隔与每分钟最多 8 次新建连接的本地限制；达到限制会额外等待，避免持续触发服务端限流。
- 无效密钥、权限、余额或配置错误不自动重试，并停止提交后续请求。修正设置后可重试未完成片段。本地解码失败只标记对应片段，不会创建该片段的付费翻译会话。
- 自动重试耗尽后，该请求对应的片段显示「失败」，其余片段继续处理。可以点击「重试此片段」或「跳过失败片段」。**跳过按钮只针对失败片段，正常处理中不能跳过。** 跳过后仍可手动重试。
- 已完成的译文保留；重试只重发选中的片段，成功后替换该片段旧的部分结果，避免重复字幕。重试会重复调用该段音频，可能再次计费。
- 整体取消后，可用「重试未完成片段」继续本次窗口中未完成的任务；该按钮不会重新处理已完成或主动跳过的片段。重试沿用上次目标语言和词典方向；空闲时重试会读取新保存的密钥与词典内容。「重新翻译」则从头开始。退出应用后不保留恢复队列。

## 文件与词典

- 可选择 WAV、MP3、M4A、AAC、FLAC、OGG。桌面应用使用本机 FFmpeg / ffprobe 读取时长、逐段解码，单个原文件最多 16 GiB、24 小时。
- 初始按 20 分钟规划，可改为 5、10、20 或 30 分钟；开始时加速模式会进一步细分请求。超过原来的 100 MiB / 30 分钟限制时，不需要先压缩整个文件。
- 在本机解码为 16kHz 单声道 PCM16；原生解码逐个准备，最多保留两个在处理的分段缓存，完成后释放。不会把整个长音频解码到内存，也不会播放音频来进行识别。
- FFmpeg 和 ffprobe 需要已安装在本机的 PATH、常见 Homebrew 目录或应用可执行文件旁；当前安装包未内置这两个工具。本机已检测到可用工具。其他电脑缺少工具时，页面会提示手动导入已切分文件。
- 词典默认不使用；可以明确选择已保存的「我的话 → 对方」或「对方 → 字幕」词典。选择前确认其中译法适合本次目标语言。
- 翻译期间可以取消；已经完成的文字保留，可导出部分结果，或只重试未完成的片段。

## 自动失败与手动切分

选择文件后会显示分段时间范围。若当前段解码失败，可缩短自动分段时长后点击「重新分段」，也可以选择手动分割点。

手动分割点支持秒数、`分:秒`、`时:分:秒`，可包含小数，每行一个或用逗号分隔。例如 45 分钟的文件填写 `15:00, 30:00`，将生成三段。起点 0 和文件终点自动补齐；分割点不能重复、越界，每段最长 30 分钟。点击「应用分割点」确认后才能开始翻译，可先点击分段列表试听边界。

如果缺少本地解码工具、文件时长无法读取，或调整分割点仍不能解码，点击「导入已切分音频」，选择自己切好的一个或多个文件。每个文件须不超过 100 MiB、30 分钟，且能被系统解码为单声道或双声道音频。这一路径不依赖 FFmpeg，按文件名中的数字自然排序，例如 `part-2` 在 `part-10` 前；开始前请检查列表顺序。

手动导入的文件应当是原录音连续、不重叠、不缺失的片段。应用按各文件时长拼接字幕时间轴；如果切分时删除了停顿或漏掉片段，合并后的字幕就不再对应未删减的原录音。最多导入 500 个片段，总时长最多 24 小时。

## 对齐与回放

译文段落显示相对原音频起点的开始、结束时间。时间取自 Qwen `speech_started.audio_start_ms` 和 `speech_stopped.audio_end_ms`，按原文项 ID 关联译文，再加上该分段在原音频中的起始时间，不使用网络返回时间。不同分段的原文项 ID 相互隔离；同一原文段落的多条译文合并为一条字幕。

点击一段译文，会跳到原音频对应位置播放，到该段结束处暂停。手动导入多个文件时，会切换到该字幕所属文件的对应位置。也可用播放器连续播放当前文件、拖动进度或调整速度；播放中的段落会高亮。回放前会停止实时声音采集，避免原音被再次识别。

时间是语音段级别，而不是逐字强制对齐，识别和断句仍会有模型误差。如果服务端未返回某段完整时间戳，该段显示「时间未对齐」，不提供猜测的定位时间，SRT/VTT 导出会等待完整时间信息，TXT 仍可用。

## 导出

选择「译文」「原文」或「原文与译文」，点击 SRT、VTT 或 TXT，在系统保存对话框中选择位置。

- SRT/VTT 使用原音频的时间轴，可与原文件配合播放。
- TXT 只包含文字，不附带字幕时间轴。
- 取消或失败后的导出默认文件名标注「部分结果」。
- 跳过的片段会留下对应时间空缺，后续字幕不会前移；如果失败前已有部分定稿文字，这些文字仍可导出。
- 当前文件与结果保留在本次应用窗口中；更换文件或退出前请导出。分段音频缓存在处理完成、取消或关闭时清理，不会自动上传整个原文件到公共存储。

## 验证

自动化测试覆盖分段规划、逐段解码和缓存释放、全局时间偏移、跨分段 ID 隔离、发送节奏、取消、失败保留部分结果、晚到的原文和时间戳、严格收尾确认、字幕导出、点击回放和边界停止。原生播放按范围读取选中的文件，不接受任意文件路径。原生导出使用完整写入临时文件后再替换目标文件，写入失败保留旧文件。

分段功能已使用 31 分钟、178,560,044 字节的 WAV 验证晚段寻址，并验证小数毫秒边界和运行中取消；MP3、M4A、AAC、FLAC、OGG 实际分段解码通过。加速与恢复测试覆盖两路并发上限、单路准备与缓存释放、自动退避、仅跳过失败请求、迟到事件隔离、重试替换部分结果和取消后继续。

2026-10-28：209 项 JavaScript 测试和 27 项实际原生 Rust 测试通过。真实浏览器使用实际界面与控制器、本地模拟服务完成了「两段成功、一段重试后失败 → 跳过失败段 → 单独重试成功」验证，其他两段保持第 1 次请求且字幕未重复。此验证未调用百炼。Mac Apple Silicon 调试版位于 `dist/audio-recovery/MyTranslator Dev.app`。
