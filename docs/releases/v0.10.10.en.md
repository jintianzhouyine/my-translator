Add lyrics-style desktop captions with source and translation options for your speech, the other person's speech, or both speakers.

## Changes

- Enable **桌面字幕** (Desktop captions) in **设置 → 显示设置** (Settings → Display), or toggle it from **更多 → 桌面字幕** in the live view. The separate transparent, always-on-top window supports dragging, resizing and a close button shown on hover, without taking keyboard focus.
- Choose source and translation, source only, or translation only, and select your speech, the other person's speech, or both. Desktop captions are off by default. Preferences are saved immediately and apply without interrupting recognition or changing translated audio output.
- Reuse existing live translation results without starting another capture or cloud session. Qwen pairs text by direction and sentence ID, updating matching sentences when source text arrives late. Previously recognized sentences keep their speaker identity after an audio source switch.
- Desktop preferences are independent of bilingual display in the main window. Clearing the main transcript clears desktop captions; Pause and Stop retain the latest sentence. Closing the caption window during a settings save now preserves the disabled state.

Qwen requires duplex mode to capture your own speech. Other engines treat microphone input as you and system audio as the other person; choose both speakers when capturing both inputs together. See [live and desktop captions](https://github.com/jintianzhouyine/my-translator/blob/v0.10.10/docs/live-subtitles.en.md).

## Manual build

This version is prepared as a Release draft for you to trigger manually. In [Build & Release](https://github.com/jintianzhouyine/my-translator/actions/workflows/release.yml), click **Run workflow**, select **main**, and enter **`v0.10.10`** to start a new manual run.

After both platforms pass, the workflow uploads and publishes:

- `MyTranslator_0.10.10_aarch64.dmg`
- `MyTranslator_0.10.10_x64-setup.exe`
- `SHA256SUMS`

## Validation scope

All 370 JavaScript application tests passed, covering content and speaker selection, streaming updates, delayed source text, IPC ordering, settings failures, concurrent close/save and speaker identity after an input switch. The new native subtitle module passed type checking against Tauri 2.10.3, with three Rust module tests for payloads and settings compatibility.

Browser checks covered 900×180 and 400×180 captions, hover controls and settings persistence/toggle synchronization. Version consistency, formatting of modified Rust files, Git diff checks and strict LeanSpec validation passed.

A previous complete Cargo test attempt could not reach app compilation because the local index update stalled and the offline cache lacked `bumpalo`. Complete native packaging and real calls, native transparent window behavior and audio devices have not been verified. Complete macOS and Windows tests and installer results depend on the manual CI run.
