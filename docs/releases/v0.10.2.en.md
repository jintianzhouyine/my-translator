Fix long periods without output while preparing speech libraries in Windows x64 builds.

## Changes

- Separate logs for download, validation and extraction; lengthy operations periodically report progress or elapsed time.
- Added connection, low-speed and overall download timeouts, with up to three attempts. Extraction also has a time limit.
- Check the official speech-library archive's size and SHA-256 before using it.
- Cache validated speech libraries separately to avoid repeated downloads in later builds.
- Retain Apple Silicon Mac and Windows x64 releases, with no changes to translation features or models.

## Downloads

- **Apple Silicon Mac**: `MyTranslator_0.10.2_aarch64.dmg`.
- **Windows x64 (Intel/AMD 64-bit)**: `MyTranslator_0.10.2_x64-setup.exe`.
- `SHA256SUMS` contains installer checksums.

Historical Windows ARM64 installers remain available in [v0.10.0](https://github.com/jintianzhouyine/my-translator/releases/tag/v0.10.0).
Automatic audio decoding and splitting still require separately installed FFmpeg / ffprobe; translated call audio requires a compatible virtual audio device.
Qwen requires your own Bailian API key, workspace and region.

## Validation scope

The release workflow runs JavaScript / Rust tests, installer builds, and architecture and version checks on both platforms, publishing attachments only after all pass.
New regression tests cover retries after download failures, rejection of corrupt archives, cache restoration and subprocess timeouts.
Installation on real devices, cloud translation and meeting audio routing still require validation on target computers.

macOS uses an ad-hoc signature, without an Apple Developer signature or notarization. The Windows installer has no publisher certificate.
