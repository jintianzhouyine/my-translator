Fix the unsupported macOS build runner and keep error notices visible for two seconds.

## Changes

- Switch macOS builds to `macos-15` ARM64 while retaining Apple Silicon installers. GitHub retired macOS 14 images on November 2, 2026, causing `macos-14-arm64-us-default is not supported` with the old configuration. See the [official announcement](https://github.com/actions/runner-images/issues/13518).
- Error notices remain visible for two seconds from display. Subsequent status notices no longer replace them immediately. Pending notices are coalesced, prioritizing the latest error; stale timers cannot remove a new notice. Ordinary notices still last three seconds.
- Includes the previous live translation recovery, seven-day diagnostic logs and Tauri error-channel compilation fix.

## Manual build

This Release is a draft; no build has been triggered. In [Build & Release](https://github.com/jintianzhouyine/my-translator/actions/workflows/release.yml), click **Run workflow**, select **main**, and enter **`v0.10.9`** to start a new manual run.

Do not rerun an old job: it retains the original workflow configuration. After both platforms pass, the workflow uploads and publishes:

- `MyTranslator_0.10.9_aarch64.dmg`
- `MyTranslator_0.10.9_x64-setup.exe`
- `SHA256SUMS`

## Validation scope

All 350 JavaScript application tests passed, including five regression tests for notice timing, subsequent messages and stale timers. Workflow YAML, manual triggers, platform matrix, version consistency, diff checks and LeanSpec validation passed.

No remote build was run for this change. Complete macOS and Windows testing and installer results depend on the manual CI run.
