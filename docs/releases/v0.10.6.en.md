Fix intermittent failures in the system-audio-device confirmation test under CI scheduling delays. Includes v0.10.5's live-call audio controls and device restoration.

## Changes

- Use a controllable clock in audio-device confirmation tests to verify stability directly, rather than relying on real sleep scheduling or observation counts.
- Added tests for stability-timer resets, delayed wakeups, switch timeouts and read errors. Actual device switching still requires 100 milliseconds of stability, with a 20-millisecond polling interval and a 2-second timeout.
- Includes independent original / translated audio toggles and volumes at the upper right of the live page, system-default audio-device restoration after stopping, and engine-selection memory.

## Installers and builds

This Release starts as a draft. In [Build & Release](https://github.com/jintianzhouyine/my-translator/actions/workflows/release.yml), select `main`, enter tag **`v0.10.6`**, and trigger the build manually.

After tests, packaging and architecture checks pass on both platforms, the workflow uploads the installers and publishes:

- **Apple Silicon Mac**: `MyTranslator_0.10.6_aarch64.dmg`.
- **Windows x64 (Intel/AMD 64-bit)**: `MyTranslator_0.10.6_x64-setup.exe`.
- `SHA256SUMS`: installer checksums.

The `v0.10.5` tag still points to the original commit; rerunning that version will not include this fix. Creating a draft and pushing the new tag do not automatically trigger builds.

## Usage notes

Automatic switching supports BlackHole on macOS and standard-name VB-CABLE devices on Windows (including A/B/C/D). Use the system-default microphone in meeting applications, and preferably use headphones for playback. For other virtual devices, turn off automatic management and configure routing manually.

Original audio is off by default and translated audio is on. Both can be adjusted independently. When both are enabled, delayed translations may overlap with original speech. After a forced process termination, device recovery is attempted at the next startup.

## Validation scope

This change passed 282 JavaScript tests and 14 isolated Rust tests directly referencing the actual system-audio-device module. The latter include 4 switch-confirmation tests and 10 device-route recovery tests. Formatting checks for modified files, diff checks and strict LeanSpec validation also passed.

The local temporary Cargo dependency cache was incomplete, so the application's full native Rust tests were not rerun. Isolated tests do not establish that the complete application builds successfully.

Platform installers depend on this version's manually triggered CI result. End-to-end calls with real cloud translation, virtual audio devices and meeting applications still require validation on target computers.

macOS uses an ad-hoc signature, without an Apple Developer signature or notarization. The Windows installer has no publisher certificate.
