Fix unexpected live-translation stops and sessions that appear active without translating. Add seven days of local diagnostic logs.

## Changes

- Qwen reconnects only the affected direction after a temporary failure, with up to three consecutive retries while the other direction continues. Pause and Stop cancel reconnection.
- Fix duplicate OpenAI close notifications creating competing connections and capture sessions. Correct Soniox handling of normal server closes, failed session rotation and stale callbacks.
- Add bounded connection operations and transport heartbeats. Silence alone is not treated as a failure. Audio capture failures report an error and update the running state.
- Allow up to 30 seconds of translated speech buffering instead of ending the whole call when a long sentence exceeds the old five-second limit. Excess stale speech is skipped with a warning while captions continue.

## Diagnostic logs

Open **设置 → 关于 → 打开日志目录** (Settings → About → Open log folder). On Windows, the default directory is `%APPDATA%\com.personal.translator\logs`.

Files use local calendar dates and retain today plus the previous six dates, with automatic cleanup and a 5 MiB daily limit. Events include version, translation start/pause, connection state, retry attempt and predefined error category. Logs exclude credentials, recordings, transcripts and raw provider error messages.

## Manual build

This Release starts as a draft; no build is triggered. In [Build & Release](https://github.com/jintianzhouyine/my-translator/actions/workflows/release.yml), select **main**, enter **`v0.10.7`**, and run the workflow manually.

After both platforms pass, the workflow uploads and publishes:

- `MyTranslator_0.10.7_aarch64.dmg`: Apple Silicon Mac.
- `MyTranslator_0.10.7_x64-setup.exe`: Windows x64.
- `SHA256SUMS`: installer checksums.

## Validation scope

All 344 JavaScript application tests passed. The actual native log core passed nine directly compiled tests. Isolated mixer, capture-forwarding and heartbeat logic passed 20 tests, and native log allowlist formatting passed two tests. Changed-file formatting, diff checks and strict LeanSpec validation passed.

The full local native build remains unverified because dependency downloads timed out and the offline cache was incomplete. Core and isolated tests do not establish that the complete application builds. Full macOS and Windows validation and installers depend on the manually triggered CI run; real cloud and meeting-device behavior still requires testing on target machines.

Reconnection resumes with new audio and does not replay the interruption. Windows calls remain bound to the selected playback device; reselect and restart if the meeting application switches to another device.
